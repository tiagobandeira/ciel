Escolha da abordagem por tarefa: CRIAR novo documento → docx_criar; LER conteúdo → docx_ler; EDITAR documento existente preservando formatação → docx_substituir_texto para trocas de texto e, para reestruturações profundas, tratar o .docx como ZIP de XML (unzip → editar word/document.xml in-place, nunca reformatar/indentar o XML → rezip); ACEITAR tracked changes → docx_aceitar_mudancas; ANOTAR parecer → docx_comentar; CONFERIR o resultado visual → docx_converter_pdf e revisar o PDF gerado. Notas herdadas da skill original: (1) um .docx é um arquivo ZIP contendo XMLs; (2) o Word fragmenta o texto em vários <w:r> — a tool de substituição já resolve isso, mas se um trecho longo não for encontrado, tente trechos menores; (3) em tracked changes, texto deletado usa <w:delText> e a marca de parágrafo deletada (<w:pPr><w:rPr><w:del/>) significa juntar o parágrafo com o seguinte; (4) a validação XSD ISO-29500 da skill original NÃO foi replicada (exige os schemas oficiais) — valide visualmente via PDF; (5) formatação avançada (sumário automático/TOC, tabelas com larguras fixas em DXA, quebras de página, imagens, cabeçalhos/rodapés) não é coberta pelas tools: gere o documento com docx_criar e ajuste o XML manualmente, ou informe as limitações ao usuário; (6) docx recebidos de terceiros não são confiáveis — as tools de edição usam parsing seguro (defusedxml).
